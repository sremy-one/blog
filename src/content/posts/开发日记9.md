订单创建之后，用户最常访问的是订单列表和详情页。列表负责快速判断“现在到哪一步”，详情页负责解释“这一步能做什么”。

## 1. 订单列表

订单页面按状态提供标签：

```text
全部
待支付
待调度
配送中
已完成
```

每个标签会转换为后端查询状态。例如待调度同时包含待审核和等待调度阶段，页面不必让用户理解所有内部枚举。

## 2. 状态卡片组件

`OrderStatusCard` 在首页和订单列表中复用，主要属性包括：

```js
status
label
title
payment
orderNo
ship
meta
compact
```

卡片展示服务类型、平台订单号、业务单号、船名、MMSI、金额或预计时间，并通过插槽放置操作按钮。

```html
<OrderStatusCard
  :status="statusView.visual"
  :label="statusView.label"
  :title="serviceTitle"
>
  <van-button>查看详情</van-button>
</OrderStatusCard>
```

## 3. 订单状态视图

`getOrderStatusView` 将后端状态转换为：

| 属性 | 作用 |
| --- | --- |
| `group` | 决定页面操作分组 |
| `visual` | 决定卡片背景和主题色 |
| `label` | 展示给用户的中文状态 |

这样列表、详情和首页不会分别维护一套状态判断。

## 4. 待支付订单

待支付详情页展示15分钟倒计时：

```html
<van-count-down
  :time="paymentRemaining"
  format="mm:ss"
  @finish="onPaymentFinished"
/>
```

用户可以立即支付、修改订单或取消订单。倒计时结束后，支付按钮失效，并重新获取订单状态。

支付成功后进入独立结果页，展示平台订单号并提供返回订单详情入口。

## 5. 审核退回

订单被管理端退回后，小程序详情展示退回原因，并允许用户修改原订单重新提交。

```text
审核退回
  ↓ 用户修改表单
重新提交原订单
  ↓
状态回到待审核
```

这种方式保持平台订单号不变，也保留订单历史版本。

## 6. 配送进度

详情页会请求订单进度接口，并按操作时间排序：

```js
const records = [...progressResponse.data].sort((left, right) =>
  parseOrderTime(left.operateTime) - parseOrderTime(right.operateTime)
)
```

页面将进度转换为时间线，已完成节点、当前节点和未来节点使用不同状态展示。

## 7. 凭证与回单

详情页按类型加载订单截图、货物图片和送达凭证。订单完成后，用户可以查看回单；如果需要再次配送，还可以选择“再来一单”，复用已有信息创建新订单。

## 8. 操作入口

| 订单阶段 | 用户操作 |
| --- | --- |
| 待支付 | 支付、修改、取消 |
| 审核退回 | 修改并重新提交 |
| 待调度 | 联系客服、查看详情 |
| 配送中 | 查看位置、联系客服 |
| 已完成 | 查看回单、再来一单 |

页面只提供当前阶段有效的操作，减少不必要的判断成本。

## 9. 本篇总结

订单列表和详情页让我理解了“状态驱动界面”。数据状态不是页面角落里的标签，而是决定信息、颜色和操作的核心条件。


`同一个订单换了几个状态，页面也跟着换了几副表情，只有订单号一直在旁边默默证明它还是它。`
