实时大屏强调“此刻”，报表快照强调“某个时间段发生了什么”。日报、周报和月报切换后，核心指标、趋势、来源结构和超时数据都必须同时改变。


## 1. 页面指标

`src/views/manage/report-snapshot/index.vue` 展示订单总量、完成率、平均配送时长、超时数、异常数和取消数，并用三张图展示平台占比、趋势和超时/价格比较。

| 区域 | 图表 | 问题 |
| --- | --- | --- |
| 平台结构 | 环形图 | 订单主要来自哪里 |
| 订单趋势 | 折线图 | 当前周期如何变化 |
| 超时与价格 | 柱状图 | 哪些日期或类别值得关注 |

## 2. 周期切换

```js
const activePeriod = ref('day')

watch(activePeriod, () => loadReport())
```

不同周期可以对应不同接口，也可以使用同一接口的 `period` 参数。页面不直接绑定原始响应，而是先通过 `applyReportData` 转成统一模型。

```js
function applyReportData(data = {}) {
  summary.value = normalizeSummary(data.summary)
  compare.value = normalizeCompare(data.compare)
  platformData.value = normalizePlatform(data.platform)
  trendData.value = normalizeTrend(data.trend)
  nextTick(renderCharts)
}
```

统一模型让图表配置不必判断“日报字段叫 todayTotal、月报字段叫 monthTotal”。接口差异在适配层结束，组件只消费稳定结构。

## 3. 防止请求竞态

快速点击“日、周、月”会产生多个并发请求。较早发出的请求可能最后才返回，从而覆盖最新选择。页面使用版本号识别过期响应：

```js
let requestVersion = 0

async function loadReport() {
  const currentVersion = ++requestVersion
  const response = await fetchReport(activePeriod.value)
  if (currentVersion !== requestVersion) return
  applyReportData(response.data)
}
```

这段代码很短，却能解决非常隐蔽的“切换后偶尔显示错周期”问题。

## 4. 图表实例集中管理

```js
const charts = []

function initChart(el, option) {
  const chart = echarts.init(el, null, { renderer: 'canvas' })
  chart.setOption(option)
  charts.push(chart)
  return chart
}

function resizeCharts() {
  charts.forEach(chart => chart.resize())
}
```

组件卸载时遍历 `dispose()`，窗口改变时统一 `resize()`。集中管理避免每张图各自注册窗口事件。

## 5. 图表配置中的可读性

平台占比使用环形图并在中心显示总量；趋势图使用平滑折线但保留数据点；柱状图使用渐变色突出超时或价格差异：

```js
itemStyle: {
  color: new echarts.graphic.LinearGradient(0, 0, 0, 1, [
    { offset: 0, color: '#4b8cff' },
    { offset: 1, color: '#1769e8' }
  ]),
  borderRadius: [6, 6, 0, 0]
}
```

图表配置不是越复杂越好。tooltip、单位、空数据和小数精度比炫酷阴影更直接影响理解。

## 6. 同比/环比的表达

比较值除了数字，还要表达方向和好坏。订单量增加通常是正向，异常率增加却是负向。因此不能简单地把“上升”都涂成绿色，而应根据指标语义决定颜色。

```js
function trendTone(value, lowerIsBetter = false) {
  const rising = Number(value) > 0
  const positive = lowerIsBetter ? !rising : rising
  return positive ? 'positive' : 'negative'
}
```

## 7. 接口失败与演示数据

开发阶段页面保留可控的 mock 回退，正式环境则展示明确空状态。回退数据只能用于布局联调，不能伪装成真实运营结果。报表页面的可信度比“永远有图”更重要。

## 8. 本篇小结

### 快照和实时查询的区别

如果报表数据来自已经生成的快照，页面应展示快照生成时间，不能把它标成“实时”。快照适合固定口径和快速打开，实时聚合适合临时查询；两者可以同时存在，但必须让用户知道自己看到的是哪一种。

### 指标校验

联调时我会做几组关系校验：完成数不能大于总订单数；完成、取消、异常等分类之和与总量的差异要能解释；平台占比的分母一致；趋势点日期不重复且按时间递增。前端不会替后端修正业务数据，但可以在开发环境输出警告，尽早发现字段映射错位。

导出报表时同样携带当前周期与筛选参数，文件名包含周期和生成时间。页面图表、指标卡和导出文件共享同一查询上下文，才能称为同一份报表。

报表快照的难点不在画三张图，而在周期、口径、竞态和生命周期。把这些基础工作做好以后，图表才是一张报告；否则它只是一组很会变颜色的 canvas。
