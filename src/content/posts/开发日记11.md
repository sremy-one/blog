查看位置页面是小程序中最能体现无人机配送特点的页面。用户看到的是一张地图、一条蓝色航线和几个图标，代码需要处理的却是坐标来源、坐标系、轨迹进度、地图缩放和 marker 锚点。

## 1. 页面数据

轨迹页面主要维护：

```js
const latitude = ref(31.820567)
const longitude = ref(117.227267)
const mapScale = ref(15)
const polyline = ref([])
const markers = ref([])
```

页面加载订单 ID 后请求轨迹接口，并把返回数据转换为地图需要的结构。

## 2. 兼容多种坐标字段

不同任务或航线数据可能使用不同字段名，因此先统一坐标点：

```js
function normalizePoint(data, latKeys, lngKeys) {
  const lat = Number(pickFirst(data, latKeys))
  const lng = Number(pickFirst(data, lngKeys))
  return Number.isFinite(lat) && Number.isFinite(lng)
    ? { latitude: lat, longitude: lng }
    : null
}
```

数组坐标、对象坐标和 JSON 字符串也会在解析阶段转换为同一种结构。

## 3. 坐标系转换

无人机航线可能来自 WGS84、CGCS 或 GPS 数据，而微信地图使用 GCJ-02。页面会根据接口标识判断是否转换：

```js
return coordinateSystem.includes('WGS')
  || coordinateSystem.includes('CGCS')
  || coordinateSystem.includes('GPS')
```

如果坐标系处理错误，整条航线都会出现整体偏移。

## 4. 航线绘制

路线使用 `polyline` 绘制，并根据飞行进度拆成已飞和未飞两部分：

```text
已飞路线 -> 实线
未飞路线 -> 虚线
```

页面按每一段真实地理距离计算累计进度，而不是简单按照数组下标平均分配。

```js
const distances = points.slice(1).map((point, index) =>
  distanceBetween(points[index], point)
)
```

## 5. 无人机位置

根据任务开始时间和预计时长计算进度，再从整条航线上插值得到无人机坐标：

```js
const elapsed = Date.now() - animationStartedAt
const progress = Math.max(0, Math.min(1, elapsed / animationDurationMs))
renderRoute(progress)
```

定时器每秒更新一次 marker 和路线，页面卸载时及时清理。

## 6. Marker 锚点

地图坐标对应的是 marker 图片中的一个 anchor，而不是图片左上角。

```js
{
  anchor: { x: 0.5, y: 0.625 }
}
```

起点和终点图标的 anchor 应落在图钉尖端，无人机图标则使用视觉中心。图片自身的透明画布和宽高比也要纳入计算，否则缩放地图时会产生悬浮感。

## 7. 视野范围

航线加载完成后，调用地图上下文自动包含全部轨迹点：

```js
mapContext.includePoints({
  points: routePoints,
  padding: [80, 48, 380, 48]
})
```

底部需要为配送信息卡片留出空间，因此下方 padding 明显更大。

## 8. 降级路线

如果接口暂时没有返回完整航线，页面会尝试使用起点和目的地；仍然不足时才使用演示路线，并明确标记当前处于降级展示状态。

```text
正式航线
  ↓ 不存在
起点 + 目的地
  ↓ 仍不足
降级路线
```

## 9. 本篇总结

地图页面让我意识到，经纬度只是开始。坐标系、图片画布、锚点、地图视野和路线进度共同决定用户看到的无人机是否真的“飞在航线上”。


`地图最神奇的地方是：只差几个小数点或一个锚点，飞机就能当场表演悬浮术。`
