订单列表解决的是“某一单发生了什么”，报表和权限解决的是“整个平台运行得怎么样，以及谁能做什么”。当页面从一张订单扩展到全局视角后，数据口径和权限边界就变得更重要。

## 1. 管理端运营视角

管理端除了订单和异常，还包含：

| 模块 | 作用 |
| --- | --- |
| 工作台 | 展示订单、配送和异常概览 |
| 报表快照 | 保存某个统计周期的汇总结果 |
| 消息通知 | 查看系统通知及发送状态 |
| 微信用户 | 查看小程序用户基础信息 |
| 用户地址 | 查看船舶收货地址数据 |
| 用户评价 | 汇总订单服务评价 |
| 敏感操作配置与记录 | 管理高风险操作并保留审计信息 |

## 2. 报表指标

报表页面会把接口数据转换为可读指标：

```js
metric('异常率', formatDecimal(summary.exceptionRate, 2), '%')
```

常见指标可以分为：

```text
订单规模：新增订单、完成订单、取消订单
履约质量：按时送达率、异常率、平均配送时长
业务结构：快递订单、外卖订单、不同状态占比
服务数据：反馈数量、处理完成率、评价结果
```

## 3. 数据快照

实时数据适合查看当前状态，快照数据适合比较不同日期或周期。报表快照模块保存统计时间、指标值和生成记录，使运营人员能够回看历史情况。

```text
业务数据 -> 指标计算 -> 生成快照 -> 报表展示/导出
```

## 4. 可视化并不只是画图

ECharts 负责柱状图、折线图和占比图，但图表之前需要先确定口径：

- 统计的是订单数量还是配送任务数量；
- 异常率的分母是全部订单还是已履约订单；
- 时间按照创建时间、支付时间还是完成时间归属；
- 补发子订单是否计入订单规模。

如果口径不清楚，图画得越漂亮，误解可能越直观。

## 5. 角色权限

需求中定义了系统管理员、运营主管、运营人员、客服人员和飞手等角色。

| 角色 | 主要权限 |
| --- | --- |
| 系统管理员 | 系统配置、账号角色、日志、全部数据 |
| 运营主管 | 全部业务、异常处理、报表和导出 |
| 运营人员 | 订单审核、配送调度、异常处理 |
| 客服人员 | 用户沟通、异常反馈登记 |
| 飞手 | 飞行登记、轨迹查看、送达或失败确认 |

一个用户可以绑定多个角色，最终权限取角色权限合集。

## 6. 菜单权限与按钮权限

菜单权限决定页面能不能进入，按钮权限决定进入页面后能执行什么操作。

```html
<el-button
  v-hasPermi="['manage:delivery-order:approve']"
  type="primary"
>
  审核通过
</el-button>
```

即使用户能够查看订单详情，也不一定拥有审核或确认送达权限。页面展示和接口校验都要遵守同一套规则。

## 7. 敏感操作留痕

退款、取消、数据导出和关键配置修改都属于需要关注的操作。敏感操作记录应包含：

- 操作账号；
- 操作时间；
- 操作对象；
- 操作内容；
- 操作结果；
- 权限来源。

这让系统不仅能完成业务，也能解释业务是怎样被完成的。

## 8. 本篇总结

管理端越往后做，越不像单纯的 CRUD。报表要求统一数据口径，权限要求明确角色边界，审计要求保留真实操作过程。

![管理端报表与权限](./images/dev-diary-6/01.png)

`表格让我看见一条数据，报表让我看见一段趋势，权限则提醒我：不是所有看见的人都能顺手点一下。`
