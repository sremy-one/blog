飞行模块同时面对两套数据：项目数据库中的配送任务，以及大疆运载云端互联平台中的设备、航线和任务。两者不能完全混为一体，否则第三方接口一旦变化，订单详情也会跟着失效。

## 1. 本地任务保存业务关系

`HyFlightTask` 负责连接订单和外部飞行数据，保存当前任务 ID、大疆任务 ID、航线标识、任务状态等信息。订单通过 `currentTaskId` 指向当前飞行任务，过程日志也可以记录同一个任务 ID。

本地表回答“这次配送使用哪个飞行任务”，大疆平台回答“设备、航线和实时任务现在怎样”。职责分开后，即使外部平台暂时不可用，订单关系仍然存在。

## 2. 通用客户端统一鉴权

`DjiApiClient` 封装 GET、POST、PUT、DELETE 和表单请求。每次调用都会生成：

```text
X-DJI-Access-Key
X-DJI-Timestamp
X-DJI-Nonce
X-DJI-Signature
```

签名使用请求方法、时间戳和随机数等信息计算，AccessKey 与 SecretKey 只从服务端配置读取。前端永远不接触密钥，也不负责生成签名。

客户端还统一处理连接超时、请求超时、JSON 序列化、非 2xx 响应和空响应。业务 Service 不需要在每个 API 方法里重复这些代码。

## 3. OpenAPI Service 只表达业务动作

通用客户端之上再建立 `DjiOpenApiServiceImpl`，提供设备、拓扑、直播、航线、地图元素、指令和任务等方法：

```java
listDevices(params)
getWayline(waylineId, params)
createTask(body)
startTask(taskId, params)
getTaskTrack(taskId, params)
```

Service 负责拼接带 `groupId` 的路径并编码路径参数，Controller 只转发经过权限校验的请求。这样第三方 URL 变化时，修改集中在适配层。

## 4. 订单轨迹如何拿到航线

用户查看订单轨迹时，后端先查本地飞行任务，再尝试找到大疆原始航线 ID，随后请求航线详情。第三方返回的点字段可能使用 `longitude/lng/lon` 与 `latitude/lat` 等不同命名，因此要先归一化：

```java
Double lng = numberValue(pickFirst(point,
        "longitude", "lng", "lon"));
Double lat = numberValue(pickFirst(point,
        "latitude", "lat"));
```

无效坐标和零坐标会被过滤，高度与速度存在时再附加到结果中。成功获取的航线标记为 `WGS84`，让前端知道后续需要做什么坐标处理。

## 5. 第三方失败不能拖垮订单详情

航线是详情的增强信息，不是读取订单的必要条件。大疆接口异常时，后端不会让整个订单详情失败，而是回退到接驳点与船舶坐标组成的基础路线，并标记为 `GCJ02`。

```text
大疆航线成功 -> 返回完整航点
大疆航线失败 -> 返回起点和终点
基础坐标也不足 -> 只返回订单与任务信息
```

这种降级要根据业务重要性决定。创建或启动飞行任务失败不能被忽略，但展示辅助航线失败可以回退。

## 6. 本篇小结

第三方平台接入最好分成“通用 HTTP 客户端、平台能力适配、本地业务编排”三层。密钥和签名停留在服务端，外部字段在边界处归一化，再为非关键展示准备回退数据，业务代码才不会完全受制于外部接口。
